# Data and Persistence

## MVP
The initial MVP does not require a database. Messages can exist only in connected clients' in-memory UI state, so refreshing or joining late may lose access to prior messages.

## Suggested message model
| Field | Type | Notes |
|---|---|---|
| `sender` | string | Display name supplied by the client; not authenticated |
| `content` | string | Validated message text |
| `timestamp` | ISO-8601 string / Instant | Generated by the server |

## If persistence is added later
Discuss the requirement first, then choose a database based on the expected scale and operational needs. Define message retention, access controls, indexes, migration strategy, and privacy expectations. Do not imply that messages are durable until persistence is implemented and tested.
